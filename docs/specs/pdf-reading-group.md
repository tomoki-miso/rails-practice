# PDF 輪読会アプリ 仕様書

## 0. 背景

`rails-practice` リポジトリは Rails 8.1 / SQLite3 / Hotwire / Slim / RSpec が導入済みだが、ビジネスロジック（モデル・コントローラ・マイグレーション）はまだ存在しない。既存の `docs/er.md` はタスク管理アプリの ER 図で、本アプリのドメインとは別物。

本書は、これから実装する「PDF 輪読会アプリ」の **機能要件と非機能要件** を確定させ、実装着手前に合意を取ることを目的とする。実装方針（採用ライブラリ、テーブル設計、画面構成など）は本書のスコープ外とし、別途 実装計画フェーズで策定する。

---

## 1. 用語定義

| 用語 | 意味 |
| --- | --- |
| **ユーザー** | アプリにログインしているアカウント保持者。 |
| **輪読会** | 1 冊の PDF を題材にメンバーで読み合う単位。1 ユーザーが複数の輪読会に所属可能。1 輪読会につき PDF は **1 つ**。 |
| **主催者** | その輪読会を作成したユーザー。輪読会に対する管理権限を持つ。 |
| **メンバー** | 主催者から招待され、その輪読会に参加しているユーザー。主催者もメンバーに含まれる。 |
| **PDF** | 輪読会にアップロードされた PDF ファイル。1 輪読会に **1 ファイル** のみ。差し替えは可（仕様外項目あり、§4 参照）。 |
| **回（セッション）** | 1 つの輪読会内における各回の集まり（第 1 回・第 2 回 …）。1 回ごとに輪読会の PDF 内での読書範囲（開始〜終了ページ）が紐づく。 |
| **コメント** | PDF のページ単位に紐づくテキスト投稿。スレッドの起点。投稿時に種類（カテゴリ）を 1 つ選択する。 |
| **返信** | 既存コメントに対するテキスト投稿。コメントのスレッド配下に並ぶ。 |
| **予習完了** | あるユーザーが、ある「回」について事前に PDF の対象範囲を読み終えたことを示すフラグ。ユーザー × 回 で 1 件持つ。 |

## 2. 機能要件

### 2.1 ユーザー認証

- **F-A1**: ユーザーはメールアドレスとパスワードでサインアップできる。
- **F-A2**: ユーザーはメールアドレスとパスワードでログインできる。
- **F-A3**: ログイン中のユーザーはログアウトできる。
- **F-A4**: 未ログインユーザーは、保護されたページへアクセスしようとした場合にログイン画面へ誘導される。
- **F-A5**: ユーザーは表示名（ニックネーム）を持ち、コメント・返信に表示される。

### 2.2 輪読会

- **F-B1**: ログイン中のユーザーは輪読会を新規作成できる。作成時にタイトルと説明文を入力する。
- **F-B2**: 輪読会作成者は自動的にその輪読会の **主催者** となり、メンバーにもなる。
- **F-B3**: 輪読会は **招待制** とする。輪読会一覧画面には、自分がメンバーである輪読会のみが表示される。
- **F-B4**: 主催者は他のユーザーを輪読会に招待してメンバーに追加できる（招待方法は実装フェーズで決定。本書では「主催者がメンバーを追加できる」ことのみ要求）。
- **F-B5**: 非メンバーは、その輪読会の PDF・コメント・メンバー情報を一切閲覧できない。

### 2.3 PDF アップロード・閲覧

- **F-C1**: 主催者は、その輪読会に PDF ファイルを **1 つ** アップロードできる。1 輪読会 = 1 PDF とする。
- **F-C2**: アップロード時、PDF にタイトル（任意）を付与できる。未入力時はファイル名を採用する。
- **F-C3**: 輪読会の詳細画面に、その輪読会の PDF（タイトル・ファイル情報）が表示される。
- **F-C4**: メンバーは輪読会の PDF をブラウザ上で閲覧できる。閲覧画面では現在のページ番号が把握できる。
- **F-C5**: 非メンバーは PDF を閲覧・ダウンロードできない（直リンク含む）。

### 2.4 コメント・返信

- **F-D1**: メンバーは PDF の **特定のページ番号を指定して** コメントを投稿できる。
- **F-D2**: コメントには本文・投稿者・投稿日時・対象ページ番号・**種類** が記録される。
- **F-D3**: コメント投稿時、ユーザーは次の **種類** から 1 つを必須で選択する：**問い／気付き／感想／雑学／その他**。
- **F-D4**: PDF 閲覧画面または PDF 詳細画面で、**ページごとのコメント一覧** を確認できる（現在開いているページのコメント表示、もしくはページ番号での絞り込み）。一覧上では各コメントの種類がラベル等で識別できる。
- **F-D5**: コメント一覧は **種類でフィルタ** できる（例：問いだけ表示、気付きだけ表示）。
- **F-D6**: メンバーは既存コメントに **返信** を投稿できる。返信は親コメントに紐づき、時系列でスレッド表示される。返信は種類を持たない。
- **F-D7**: 返信に対する更なるネスト（返信の返信）は仕様外とし、1 段のスレッドとする。
- **F-D8**: コメント・返信の閲覧範囲はその輪読会のメンバーに限定される。

### 2.5 回（セッション）と読書範囲

- **F-E1**: 主催者は輪読会の中に **回（第 N 回）** を作成できる。回には回番号（自動採番でも手動でもよい）、開催日（任意）、読書範囲を設定する。対象 PDF は輪読会の PDF（1 つ）に固定される。
- **F-E2**: 読書範囲は **PDF の開始ページ〜終了ページ** で表現する。
- **F-E3**: 1 つの輪読会は複数の回を持てる。回は輪読会詳細画面に一覧表示される。
- **F-E4**: 主催者は既存の回の対象 PDF・範囲・開催日を編集できる。回の削除可否は本フェーズでは未定（YAGNI、§4 参照）。
- **F-E5**: 非メンバーは回・読書範囲を閲覧できない。

### 2.6 予習完了ステータス

- **F-F1**: 各メンバーは、自分が参加している輪読会の **各回について「予習完了」フラグ** を立てる／取り消すことができる。
- **F-F2**: 予習完了は **ユーザー × 回** で一意に管理される（同じ回に対して 1 ユーザーは 1 件のみ）。
- **F-F3**: 回の詳細画面で、その回について **誰が予習完了しているか** がメンバーに分かるよう表示される（人数・氏名一覧のいずれか以上）。
- **F-F4**: 自分の予習完了状態は輪読会の回一覧でも一目で確認できる。
- **F-F5**: 予習完了は本人のみが付け外しできる（他メンバー・主催者は他人の状態を変更できない）。

## 3. 非機能要件

### 3.1 セキュリティ

- **N-S1**: パスワードは平文で保存せず、ハッシュ化（ソルト付き）して保存する。
- **N-S2**: 認可は「輪読会メンバーかどうか」をリソースアクセスごとに必ず検証する。URL を直接叩いて他人の輪読会の PDF・コメントが見えてはならない。
- **N-S3**: アップロードされた PDF への直接 URL もメンバー限定で配信する（公開バケットや非認証ストレージへは置かない）。
- **N-S4**: CSRF, XSS の対策は Rails 標準（CSRF トークン・自動エスケープ）に従う。

### 3.2 アップロード制約

- **N-U1**: アップロード可能なファイル形式は PDF のみ（拡張子と MIME タイプの両方で検証）。
- **N-U2**: 1 ファイルあたりのサイズ上限を設ける（既定値 **50 MB**。実装時に妥当性を再検証）。
- **N-U3**: 上限超過・形式不正の場合はエラーメッセージを表示し、アップロードを拒否する。

### 3.3 性能・可用性

- **N-P1**: 同時接続ユーザー数は **練習用途として 10 人程度** を想定し、これ以上のスケーリング要件は本フェーズでは扱わない。
- **N-P2**: PDF 閲覧画面の初期表示は、50 MB 程度の PDF でも数秒以内（ローカル開発環境基準）で開始できることを目標とする。
- **N-P3**: コメント投稿・一覧表示は通常操作のレスポンスとして 1 秒以内を目標とする。

### 3.4 データ保全

- **N-D1**: PDF の削除は本フェーズでは仕様未定（YAGNI）。実装時に「不要なら作らない」方針で扱う。
- **N-D2**: コメント・返信の削除（論理／物理）も本書では指定しない（仕様外）。
- **N-D3**: 回（セッション）の削除も本フェーズでは仕様未定（YAGNI）。誤作成のリカバリが必要になった時点で再検討する。
- **N-D4**: コメントの **種類** はアプリ内に列挙値として定義し、追加・変更には実装変更を伴う（DB マスタ化はしない）。

### 3.5 開発・テスト

- **N-T1**: 機能要件 F-A〜F-F は RSpec によるテストでカバーする（最低限、認可・コメントのページ紐付け・予習完了の本人限定更新は feature/system spec で検証）。
- **N-T2**: UI は Slim + Hotwire を利用する（既存テンプレート資産との整合性のため）。

## 4. スコープ外（明示的に作らないもの）

- コメントの **解決済み** 機能。
- コメント・返信の編集／削除。
- コメント種類のユーザー定義・カスタマイズ（固定 5 種のみ）。
- 1 輪読会に複数 PDF をアップロード・管理する機能（1 輪読会 = 1 PDF 固定）。
- PDF の差し替え／削除（YAGNI、必要になった時点で再検討）。
- 回（セッション）の削除。
- 他メンバーの予習完了状態を主催者が代行で変更する機能。
- 予習完了の催促通知。
- PDF 内の座標指定アノテーション（ハイライト・矩形選択など）。本書ではあくまで「ページ番号単位」のコメントのみ。
- 全文検索（PDF 本文、コメント本文ともに）。
- 公開輪読会・参加申請フロー（招待制のみ）。
- 通知（メール・アプリ内通知）。
- 多言語対応。

## 5. 前提事項

- 本書は機能・非機能要件の合意を目的とし、ER 図・テーブル定義・画面設計・採用ライブラリは含めない。これらは別途、実装計画フェーズで決定する。
- 既存 `docs/er.md` は本アプリと無関係のため、実装フェーズで置き換えまたは別管理にする想定。
- 認証実装に Devise を使うか Rails 8 標準の authentication ジェネレータを使うか等の技術選定は、本書では問わない。

## 6. 受け入れ基準

本仕様書がそのまま実装着手フェーズへ渡せる状態かは、以下のレビュー観点で確認する。

1. **要件カバレッジ**: ユーザーが挙げた全要件（認証／輪読会作成／PDF アップロード／PDF 閲覧／ページ指定コメント／ページごとコメント一覧／返信／コメント種類／回と範囲／予習完了）が F-A〜F-F に対応していること。
2. **権限の網羅性**: 「非メンバーが何を見られないか」「予習完了は本人のみ更新可」など権限要件が明示されていること（F-B5, F-C5, F-D8, F-E5, F-F5, N-S2）。
3. **スコープ境界の明瞭さ**: 「やらないこと」が §4 に列挙されており、実装中に追加機能が紛れ込まないこと。
4. **非機能要件の測定可能性**: ファイルサイズ上限・想定同時接続数・レスポンス目標値が具体的に書かれていること（N-U2, N-P1, N-P2, N-P3）。
5. **列挙値の確定**: コメントの種類が「問い／気付き／感想／雑学／その他」の 5 種で固定されていること（F-D3, N-D4）。
